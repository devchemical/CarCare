# Use one shared shell for authenticated product views

Keepel renders one persistent application shell around authenticated product views while keeping the anonymous landing, guest-only authentication routes, and callbacks outside it. The authenticated dashboard remains at `/`; it and explicitly registered private areas such as `/vehicles*` share the same mounted top bar, desktop navigation rail, mobile drawer, account controls, and main-content boundary. The public `/privacidad` route uses that shell contextually when the visitor is authenticated and retains the public layout when anonymous. Route membership selects presentation only and never replaces server-side authentication or authorization.

## Consequences

- Future authenticated product areas opt into the shell explicitly. Authentication alone does not place an otherwise public route inside it; `/privacidad` is an explicit contextual exception and remains public and indexable.
- Navigation changes the main view without remounting the shell. The rail preference survives navigation and reloads; each destination owns its scroll position, mobile navigation closes after selection, and transient page state does not carry into the next view.
- Private loading, empty, and recoverable error states keep the shell visible. Session expiry on a private route redirects to login and removes it. External session loss on `/privacidad` keeps the policy visible and changes its presentation to the public layout, while an explicit logout retains the established login redirect.
- `/vehicles/[id]/maintenance` remains part of the Vehicles navigation hierarchy. The obsolete per-vehicle header selector is not carried forward.
- Existing Vehicles, Maintenance, and policy content is integrated without a broader visual redesign. Authenticated views omit the public header and footer. The shell account area orders identity, Privacy, cookie preferences, and logout; its interactive rows share a simple flex anatomy, uniform height and spacing, a fixed icon column, consistent collapsed alignment, visible focus, and accessible names across desktop and mobile.
- Privacy is marked as the current destination on authenticated `/privacidad`. Cookie preferences remain the existing overlay rather than a separate route; opening it from mobile navigation closes the drawer first and avoids stacked overlays.
- A richer avatar account popover and the missing `/vehicles/[id]` destination used by the dashboard's `Ver vehículo` action remain separate follow-up work.
- Acceptance covers anonymous and authenticated privacy presentation, the public/private route matrix, active navigation, shell and rail continuity, one main-content region, responsive and focus behavior, private loading and session-transition states, privacy controls, legacy-chrome removal, keyboard access, 320-pixel overflow, affected end-to-end journeys, and the repository's canonical checks.
